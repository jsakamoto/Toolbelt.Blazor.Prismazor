# Design of the Prism.js port for Blazor

## Basic policy

- The output HTML is the same as Prism (the `<span class="token keyword">` form). So the theme CSS files of Prism (MIT) work as they are, and you can switch light and dark by CSS only.
- Follow the behavior of Prism.js. When in doubt, check what Prism.js 1.30.0 really does, and match it.
- `Tokenizer.cs` is a faithful port of `tokenize` and `matchGrammar` in the Prism core (including `greedy`, `inside`, `lookbehind`, `alias`, and rematch).
- The language definitions are not written by hand. The C# code is generated by a program from the PrismJS grammars. All the languages of PrismJS 1.30.0 (288 languages) are generated.
- The hooks of the languages (before-tokenize, after-tokenize, and wrap) that the components of Prism add are ported into `Hooks/`.
- The `CodeBlock` component highlights synchronously in `OnParametersSet`. So the first response is already highlighted, even in static SSR.

## Public API

- `<CodeBlock Code="..." Language="@PrismazorLanguages.CSharp" />` outputs `<pre tabindex="0" class="language-xxx"><code class="language-xxx">...</code></pre>`. Other attributes, such as `class`, go to the `pre` element.
- `PrismazorHighlighter.Highlight(code, grammar)` returns the same HTML string as `Prism.highlight`.
- `PrismazorLanguages.CSharp` and the like are the `Grammar` of each language. The language ID is in `Grammar.Id`.
- `PrismazorLanguageRegistry.Register(grammar, aliases)` plays the role of `Prism.languages`. A language that finds another language by name uses it, such as the code blocks of Markdown. A language that is not registered is not highlighted, in the same way as a language that is not loaded in Prism.js.

## State of the grammars of the languages

In Prism.js, the grammars change depending on which components are loaded. Another language may rewrite `Prism.languages.javascript`, and a language that is listed in `optional` (for example, regex for JavaScript) works together only when it is loaded. This library takes the following state as the correct one.

- All the languages are loaded, the same as `loadLanguages()` of Prism.js without arguments. So the cooperation is on, such as highlighting regular expression literals of JavaScript with the regex language, and highlighting the front matter of Markdown with YAML.
- But the extensions that rewrite the grammar of another language are not applied to the language they rewrite. They are css-extras, js-extras, js-templates, php-extras, javadoclike, jsdoc, javadoc, phpdoc, opencl, and xml-doc. If they were applied, the output would change even for people who use only JavaScript.
- jsdoc, javadoc, phpdoc, and opencl are provided as languages. Their own grammars have the rewrite applied, and nothing else.
- The extensions that have no grammar of their own (css-extras, js-extras, js-templates, php-extras, and xml-doc) are not provided as languages.

## Key points of the implementation

1. Extraction of the grammars (`extract.mjs` and `prism-env.mjs`)
   - The grammars are written to JSON as an object graph (arrays of grammars and patterns, with references by index). This keeps objects that are shared, and circular references (for example, the doctype of markup contains markup itself).
   - `rest` is expanded at extraction time by the same rule as `tokenize` of Prism.
   - There are two kinds of PrismJS environments, by the policy of the previous section. The normal languages are extracted from the environment where all languages are loaded. A language that rewrites another one (such as jsdoc) is extracted from a separate environment that has only that language added.
   - When a language that is extracted from a separate environment refers to the grammar of another language, the grammar is shared if the content is the same, and copied if the rewrite changed it. The comparison is done on the structure of the grammar.
2. Extraction of the hooks
   - For the 13 languages that use markup-templating (php, twig, django, ejs, erb, etlua, ftl, handlebars, latte, liquid, smarty, soy, and tt2), the calls of `buildPlaceholders` are recorded. This gives the pattern, and the grammar for the part other than the placeholders. The recording is done by putting a wrapper on `prism-markup-templating.js` each time it is loaded, because the loader of PrismJS loads it again whenever it loads another language.
   - Two things in the hooks are ported by hand into `TemplatingFilters.cs` and the table in the generator. One is the conditions that are passed as functions (`replaceFilter` of liquid, smarty, and soy). The other is the check whether the PHP code has `<?`.
3. Conversion of regular expressions (`JsRegexConverter.cs`)
   - `.` becomes `[^\n\r\p{Zl}\p{Zp}]`, and `[\s\S]` when the `s` flag is on.
   - `^` and `$` with the `m` flag become lookahead and lookbehind that match the line terminators of JS (CR, LF, U+2028, and U+2029). `$` without `m` becomes `(?![\s\S])`, because `$` of .NET also matches before a final line break.
   - `\d` and `\w` are expanded to ASCII character classes.
   - `[` in a character class is escaped, because .NET reads it as a class subtraction.
   - `\W` and `\D` in a character class are expressed by rewriting the class. `[^x\W]` becomes `(?:(?![x])[a-zA-Z0-9_])`, and `[x\W]` becomes `(?:[x]|[^a-zA-Z0-9_])`.
   - An escaped letter that has no meaning in JS (for example, `\a`) becomes the letter itself, the same as JS.
   - `RegexOptions.Multiline`, `Singleline`, and `ECMAScript` are not used. The `i` flag becomes `IgnoreCase | CultureInvariant`.
   - The generator checks each converted pattern by calling `new Regex` on it.
4. Generated code (`Languages/*.g.cs`)
   - For each language, an `internal static class XxxLanguage` is made, and its static constructor builds the grammar. `Root` is made first by a field initializer, so circular references between languages do not break it.
   - The root grammar of another language (for example, JavaScript in the `<script>` of markup) is not copied. It refers to `JavaScriptLanguage.Root`.
   - `[GeneratedRegex]` is not used. A pattern is kept as a string, and `GrammarPattern.Regex` calls `new Regex` at the first use.
   - `PrismazorLanguages` exposes one property for each language. If we put a dictionary with string keys there, all the languages would stay without being trimmed.
   - By measurement, even if all languages are included, the languages that are not used are removed by the Release publish (WebAssembly).
5. Hooks (`Hooks/`)
   - The hooks are attached to the root grammar of a language (`Grammar.Hooks`). `PrismazorHighlighter.Highlight` runs only the hooks of the grammar that it receives. In Prism.js, the hooks run for all languages, and each hook checks with `env.language` whether it is for its own language.
   - For the markup-templating languages, `TemplatingHooks` runs the port of `buildPlaceholders` and `tokenizePlaceholders`.
   - `TagTextHooks` ports jsx, tsx, and xquery (the common `walkTokens`). `GraphqlHooks` ports graphql, `NaniscriptHooks` ports naniscript, and `MarkdownHooks` ports markdown.
   - Among the wrap hooks, the one in prism-markup.js that adds a `title` attribute to an entity runs in `PrismazorHighlighter` for all languages. The handling of `code-block` of markdown is done in `MarkdownHooks`.
   - `Type`, `Content`, and `Alias` of `Token` can be changed, because some hooks rewrite the content of a Prism `Token`.

## Known differences from PrismJS

- `\b`, `\B`, `\s`, and `\S` are not converted. The .NET versions consider Unicode (`\b` of JS matches only ASCII word characters, and `\s` of .NET includes U+0085 but not U+FEFF). The result may change for non-ASCII identifiers and special white space.
- The following are not supported, and the generator reports an error for them. They are the `u` and `y` flags, named groups and `\k<name>`, and two or more `\D` or `\W` in one character class. All the current 288 languages can be generated.
- Only the hooks of the language that is highlighted (the root grammar) run. Prism.js runs the hooks of all loaded languages, so for example a `code-block` of Markdown that is embedded in another language is not processed here, unlike in Prism.js.
- There are no properties for the aliases of languages (`html`, `js`, `jinja2`, `hbs`, `md`, and so on). Give the aliases to the argument of `PrismazorLanguageRegistry.Register`.
- There is no automatic loading like the autoloader plugin of Prism.js. So the code blocks of Markdown are highlighted only with the languages that are registered in `PrismazorLanguageRegistry`.
- When a numeric character reference in Markdown is out of the Unicode range, Prism.js throws an exception, but this library leaves the text as it is.
